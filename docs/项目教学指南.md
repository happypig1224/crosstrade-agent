## 第1步：项目骨架与Maven多模块搭建

### 1.1 开发思路

在开始编码之前，我们必须先搭建好项目的骨架。本项目采用Maven多模块架构，将系统拆分为四个模块，各自承担不同的职责：

```
crosstrade-agent (父工程，packaging=pom)
├── crosstrade-common   # 通用基础模块：枚举、常量、DTO、Entity、异常、工具类
├── crosstrade-core     # Agent核心模块：意图识别、安全审查、路由、记忆、RAG、工具
├── crosstrade-api      # API接口模块：SSE流式接口、会话管理、全局异常处理
└── crosstrade-app      # 启动入口模块：Spring Boot主类、全量配置文件
```

**模块依赖关系**（单向依赖，不可循环）：

```
crosstrade-app → crosstrade-api → crosstrade-core → crosstrade-common
```

**为什么要这样分层？**

- `crosstrade-common` 是最底层的基础模块，不依赖任何内部模块，提供所有模块共用的基础类型
- `crosstrade-core` 是核心业务模块，依赖common，包含所有Agent核心能力（意图识别、安全审查、记忆管理等）
- `crosstrade-api` 是接口层，依赖core，只负责暴露REST/SSE接口，不包含业务逻辑
- `crosstrade-app` 是启动入口，依赖api，包含Spring Boot主类和全量配置，是最终打包运行的模块

**技术栈版本选型理由**：

| 技术 | 版本 | 选型理由 |
|------|------|---------|
| Java | 17 | Spring Boot 3.x 最低要求，提供Record、密封类等现代语法 |
| Spring Boot | 3.5.9 | 最新稳定版，完整支持Spring AI集成 |
| Spring AI Alibaba | 1.1.2.0 | 阿里云官方Spring AI实现，原生支持DashScope/通义千问 |
| RocketMQ | 2.3.1 | 阿里云原生消息队列，Spring Boot Starter成熟 |
| Resilience4j | 2.2.0 | 轻量级容错框架，替代Hystrix |
| Milvus SDK | 2.4.4 | 开源向量数据库SDK，支持语义检索 |

## 第2步：公共基础模块 — 枚举与常量

### 2.1 开发思路

公共基础模块是整个项目的地基，所有其他模块都依赖它。我们先从枚举和常量开始，因为它们定义了系统中所有"类型"和"固定值"的统一标准。

**枚举设计原则**：
- 每个枚举值都有明确的业务含义
- 枚举值与数据库字段、Redis存储、MQ消息体中的值保持一致
- 提供 `fromValue()` 方法，用于从字符串（如LLM返回值、数据库值）反序列化为枚举

**常量设计原则**：
- Redis Key前缀统一管理，避免硬编码导致的拼写错误
- MQ Topic/Tag统一管理，确保生产者和消费者使用相同的名称
- 业务常量集中管理，修改时只需改一处

### 2.2 IntentType 意图类型枚举伪代码

```pseudo
enum IntentType:
    PRODUCT_GUID("product_guide", "产品导购")       // 用户描述需求/场景/预算，需要推荐产品
    PRODUCT_INFO("product_info", "产品咨询")         // 用户咨询产品对比/定制/售后政策
    QUOTE_NEGOTIATE("quote_negotiate", "报价谈判")   // 用户进入价格谈判环节
    UNKNOWN("unknown", "未知意图")                    // 无法识别意图的兜底类型
    
    String value    // 枚举值（与LLM输出、数据库存储一致）
    String desc     // 中文描述
    
    // 从字符串值反序列化为枚举（LLM返回值可能不在预定义类型中）
    static function fromValue(value: String) -> IntentType:
        for type in IntentType.values():
            if type.value == value:
                return type
        return UNKNOWN  // 不在预定义类型中，降级为unknown
```

## 第3步：公共基础模块 — DTO与Entity

### 3.1 开发思路

DTO（Data Transfer Object）用于在不同层之间传输数据，Entity用于与数据库表映射。

**DTO设计原则**：
- 请求DTO携带校验注解（@NotBlank等），在Controller层自动校验
- 响应DTO只包含前端需要的字段，不暴露内部实现
- 使用Java 17 Record简化不可变DTO的定义

**Entity设计原则**：
- 与数据库表字段一一对应
- 使用Spring Data JDBC注解（@Table/@Column/@Id）而非JPA注解，因为项目使用Spring Data JDBC
- 主键使用自增BIGINT

## 第5步：公共基础模块 — 工具类

### 5.1 开发思路

工具类是公共基础模块的最后一部分，提供两个核心安全工具：

1. **DfaSensitiveFilter**：基于DFA（确定有限自动机）算法的敏感词过滤器
2. **PromptInjectionDetector**：基于正则表达式的Prompt注入检测器

### 5.2 DFA敏感词过滤器设计思路

**为什么用DFA而不是正则匹配？**

- 正则匹配：对每个敏感词编译一个Pattern，逐个匹配，时间复杂度O(n*m)，n为文本长度，m为敏感词数量
- DFA算法：将所有敏感词构建成一棵字典树，逐字符遍历文本，时间复杂度O(n)，与敏感词数量无关

**DFA算法原理**：

将敏感词库构建成一棵多叉树，每个节点是一个Map，key是字符，value是子节点Map。当某个路径的叶子节点标记为"结束"时，表示匹配到一个敏感词。

例如，敏感词 ["你好", "你坏", "坏人"] 构建的DFA树：
```
根节点
└── "你" → Map
    ├── "好" → Map {isEnd=true}     // 匹配到"你好"
    └── "坏" → Map
        └── "人" → Map {isEnd=true} // 匹配到"坏人"
        {isEnd=true}                // 匹配到"你坏"
```

### 5.3 DfaSensitiveFilter伪代码

```pseudo
class DfaSensitiveFilter:
    // DFA字典树根节点
    Map<Character, Object> sensitiveWordMap = new HashMap()
    
    // 初始化：从敏感词列表构建DFA树
    function initSensitiveWordMap(sensitiveWords: List<String>):
        for word in sensitiveWords:
            addWord(word)
    
    // 向DFA树中添加一个敏感词
    function addWord(word: String):
        currentNode = sensitiveWordMap
        for ch in word.toCharArray():
            // 如果当前字符不在树中，创建新节点
            if !currentNode.containsKey(ch):
                currentNode.put(ch, new HashMap())
            // 移动到子节点
            currentNode = currentNode.get(ch)
        // 标记词结束
        currentNode.put("isEnd", true)
    
    // 检测文本是否包含敏感词
    function containsSensitive(text: String) -> boolean:
        for i from 0 to text.length()-1:
            ch = text.charAt(i)
            if sensitiveWordMap.containsKey(ch):
                // 找到起始字符，沿DFA树向下匹配
                currentNode = sensitiveWordMap.get(ch)
                j = i + 1
                while j < text.length() and currentNode.containsKey(text.charAt(j)):
                    currentNode = currentNode.get(text.charAt(j))
                    if currentNode.containsKey("isEnd"):
                        return true  // 匹配到完整敏感词
                    j++
        return false
```

### 5.4 PromptInjectionDetector伪代码

```pseudo
class PromptInjectionDetector:
    // 常见Prompt注入攻击正则模式列表
    List<Pattern> injectionPatterns = [
        Pattern("忽略以上指令|ignore previous instructions|ignore above"),
        Pattern("你现在是管理员|you are now admin|act as admin"),
        Pattern("系统提示|system prompt|show me your prompt"),
        Pattern("忘记之前的规则|forget your rules|disregard"),
        Pattern("假装你是|pretend you are|roleplay as"),
        Pattern("输出你的|output your|reveal your|print your"),
        Pattern("覆盖|override|bypass|绕过")

        return false
```

## 第8步：安全审查模块

### 8.1 开发思路

安全审查是系统的第一道和最后一道防线，分为入口审查和出口审查：

- **入口审查（InboundGuardrail）**：用户消息进入系统时，执行敏感词DFA过滤 + 防Prompt注入正则检测
- **出口审查（OutboundGuardrail）**：AI生成结果返回用户前，以20个Token为一块进行异步缓冲 + 小LLM校验

**入口审查流程**：
```
用户消息 → Step1: DFA敏感词过滤 → Step2: Prompt注入正则检测 → 通过/拦截
```

**出口审查流程**：
```
AI输出Token → 追加到OutputBuffer → 缓冲区满20个Token → 小LLM校验 → 通过则推送给前端/不通过则替换为"[内容已过滤]"
```

**出口审查的关键问题**：流式输出是逐Token返回的，如果逐Token校验会非常慢。解决方案是按20个Token为一块进行缓冲，每满一块校验一次。

### 8.2 InboundGuardrail入口安全审查伪代码

```pseudo
@Component
class InboundGuardrail:
    @Autowired DfaSensitiveFilter sensitiveFilter
    @Autowired PromptInjectionDetector injectionDetector
    
    function check(userMessage: String, sessionId: String, userId: String) -> SecurityCheckResult:
        // Step 1: DFA敏感词过滤
        if sensitiveFilter.containsSensitive(userMessage):
            log.securityWarn("敏感词拦截", sessionId, userId, userMessage)
            return SecurityCheckResult.BLOCK
        
        // Step 2: 防Prompt注入正则检测
        if injectionDetector.detect(userMessage):
            log.securityWarn("Prompt注入拦截", sessionId, userId, userMessage)
            return SecurityCheckResult.BLOCK
        
        // 审查通过
        return SecurityCheckResult.PASS
```

### 8.3 OutputBuffer Token块缓冲器伪代码

```pseudo
class OutputBuffer:
    int tokenSize = 20           // 每块Token数量
    StringBuilder buffer = new StringBuilder()
    int currentTokenCount = 0
    
    // 追加Token到缓冲区
    function append(token: String):
        buffer.append(token)
        currentTokenCount++
    
    // 缓冲区是否已满
    function isFull() -> boolean:
        return currentTokenCount >= tokenSize
    
    // 清空缓冲区并返回内容
    function flush() -> String:
        content = buffer.toString()
        buffer = new StringBuilder()
        currentTokenCount = 0
        return content
    
    // 获取缓冲区剩余内容（流式输出结束时）
    function drain() -> String:
        if currentTokenCount == 0:
            return ""
        return flush()
```

### 8.4 OutboundGuardrail出口安全审查伪代码

```pseudo
@Component
class OutboundGuardrail:
    @Autowired ChatClient smallChatClient      // 小LLM
    @Autowired DfaSensitiveFilter sensitiveFilter  // 降级时的规则过滤
    @Autowired CircuitBreakerRegistry circuitBreakerRegistry
    
    OutputBuffer outputBuffer = new OutputBuffer()
    
    // 检查并发射Token块
    function checkAndEmit(tokenChunk: String, emitter: FluxSink<ChatResponse>) -> void:
        // Step 1: 将token加入缓冲区
        outputBuffer.append(tokenChunk)
        
        // Step 2: 缓冲区满20个Token时触发校验
        if outputBuffer.isFull():
            block = outputBuffer.flush()
            
            // Step 3: 尝试小LLM校验（Resilience4j熔断保护）
            try:
                isValid = smallLlmCheck(block)
            catch CircuitBreakerOpenException:
                // 降级：仅执行规则过滤
                isValid = !sensitiveFilter.containsSensitive(block)
                log.warn("出口审查降级为规则过滤")
            
            // Step 4: 校验结果处理
            if isValid:
                emitter.next(ChatResponse(block))
            else:
                emitter.next(ChatResponse("[内容已过滤]"))
                log.securityWarn("出口审查拦截", block)
    
    // 流式输出结束时，处理缓冲区剩余内容
    function flushRemaining(emitter: FluxSink<ChatResponse>) -> void:
        remaining = outputBuffer.drain()
        if remaining.isNotEmpty():
            // 同样需要校验
            if !sensitiveFilter.containsSensitive(remaining):
                emitter.next(ChatResponse(remaining))
            else:
                emitter.next(ChatResponse("[内容已过滤]"))
    
    // 小LLM校验Prompt
    function smallLlmCheck(block: String) -> boolean:
        prompt = "判断以下内容是否包含违禁或不当信息，仅回答YES或NO: " + block
        result = smallChatClient.prompt(prompt).call().content()
        return result.trim().toUpperCase() == "YES"
```

## 第9步：意图识别模块

### 9.1 开发思路

意图识别是系统的"大脑"，决定用户消息应该走哪条处理通道。采用双层识别机制：

- **L1规则引擎**：基于关键词的快速匹配，O(1)时间复杂度，不调用LLM
- **L2 LLM语义分析**：当L1无法匹配时，降级到通义千问进行深层语义分析

**为什么需要双层？**
- L1速度快、成本低，但只能识别包含明确关键词的消息
- L2能理解语义，但速度慢、成本高，且有超时风险
- 双层结合：大部分请求被L1快速处理，只有少数模糊请求才走L2

### 9.2 RuleEngine L1规则引擎伪代码


## 第10步：业务分发路由模块

### 10.1 开发思路

业务分发路由采用**策略模式**，根据意图识别结果将请求分发到对应的Handler处理。策略模式的好处是：
- 新增意图类型时只需新增Handler实现，不修改路由器代码
- 避免if-else膨胀
- 每个Handler职责单一，便于测试和维护

## 第11步：记忆管理模块 — L1短期记忆

### 11.1 开发思路

L1短期记忆使用Redis存储当前会话的热度上下文，包括：
- 最近8轮对话（LIST结构）
- 当前任务状态（HASH结构）
- 待办事项（LIST结构）
- 对话轮数（STRING计数器）

**关键设计**：
- 滑动过期：每次对话交互时重置TTL为24小时，确保持续对话不会过期
- 8轮窗口：超出8轮时通过LTRIM裁剪，早期对话由上下文压缩处理
- 所有Key共享相同的TTL，一起过期

### 11.2 ShortTermMemory伪代码

```pseudo
@Component
class ShortTermMemory:
    @Autowired StringRedisTemplate redisTemplate
    
    // 保存消息到短期记忆
    function saveMessage(sessionId: String, role: String, content: String):
        // Step 1: RPUSH消息到List
        messageJson = serialize(role, content, System.currentTimeMillis())
        redisTemplate.rpshu(key(MESSAGE_KEY, sessionId), messageJson)
        
        // Step 2: 滑动过期 - 每次交互重置所有Key的TTL为24h
        expireAll(sessionId)
        
        // Step 3: 维护8轮窗口 - 超出时LTRIM
        round = redisTemplate.increment(key(ROUND_KEY, sessionId))
        if round > SHORT_MEMORY_ROUNDS:
            // 保留最近8轮(16条消息：每轮含user+assistant两条)
            redisTemplate.ltrim(key(MESSAGE_KEY, sessionId), -16, -1)
        
        // Step 4: 将用户加入48h活跃用户集合
        redisTemplate.opsForSet().add(ACTIVE_USERS_KEY, userId)
    
    // 加载最近对话
    function loadRecentMessages(sessionId: String) -> List<MessageItem>:
        messages = redisTemplate.lrange(key(MESSAGE_KEY, sessionId), 0, -1)
        return messages.map(this::deserialize)
    
    // 保存任务状态
    function saveState(sessionId: String, field: String, value: String):
        redisTemplate.opsForHash().put(key(STATE_KEY, sessionId), field, value)
        expireAll(sessionId)
    
    // 加载任务状态
    function loadState(sessionId: String, field: String) -> String?:
        return redisTemplate.opsForHash().get(key(STATE_KEY, sessionId), field)
    
    // 保存待办事项
    function saveTodo(sessionId: String, todoContent: String):
        redisTemplate.rpshu(key(TODO_KEY, sessionId), todoContent)
        expireAll(sessionId)
    
    // 加载待办事项
    function loadTodos(sessionId: String) -> List<String>:
        return redisTemplate.lrange(key(TODO_KEY, sessionId), 0, -1)
    
    // 重置所有Key的TTL
    function expireAll(sessionId: String):
        redisTemplate.expire(key(MESSAGE_KEY, sessionId), 24, HOURS)
        redisTemplate.expire(key(STATE_KEY, sessionId), 24, HOURS)
        redisTemplate.expire(key(TODO_KEY, sessionId), 24, HOURS)
        redisTemplate.expire(key(ROUND_KEY, sessionId), 24, HOURS)
    
    // 删除会话所有缓存（主动过期）
    function deleteSession(sessionId: String):
        redisTemplate.delete(key(MESSAGE_KEY, sessionId))
        redisTemplate.delete(key(STATE_KEY, sessionId))
        redisTemplate.delete(key(TODO_KEY, sessionId))
        redisTemplate.delete(key(ROUND_KEY, sessionId))
```

## 第14步：记忆管理模块 — 上下文压缩

### 14.1 开发思路

当对话超过12轮时，Redis中存储的对话会越来越多，大模型的上下文窗口有限。我们需要对窗口外的对话进行压缩：

1. 检测对话轮数是否超过12轮
2. 截取窗口外4条对话
3. 通过RocketMQ异步发送压缩消息（携带完整对话内容，不传ID）
4. Redis LTRIM保留窗口内8轮对话
5. MQ消费者调用小模型摘要压缩后存入Milvus和MySQL

## 第15步：记忆管理模块 — 冷启动恢复

### 15.1 开发思路

当用户几天后重新进入历史会话时，Redis短期记忆已过期被清除，这是标准的**缓存击穿**问题。冷启动恢复流程：

1. 检测Redis返回null
2. 获取Redisson分布式锁（防止多线程重复回填）
3. 双重检查DCL（获取锁后再检查一次Redis，避免重复回填）
4. 从MySQL回填最近8轮对话和PENDING待办事项
5. 设置滑动过期24h
6. 释放锁

```pseudo
    @Autowired ShortTermMemory shortTermMemory
    
    function recoverIfNeeded(sessionId: String, userId: String):
        // Step 1: 检查Redis短期记忆是否存在
        if redisTemplate.hasKey(key(MESSAGE_KEY, sessionId)):
            return  // 缓存命中，无需恢复
        
        // Step 2: 获取Redisson分布式锁
        lock = redissonClient.getLock(key(COLDSTART_LOCK_KEY, sessionId))
        
        try:
            // Step 3: 尝试获取锁，等待3s，锁自动释放10s
            locked = lock.tryLock(3, 10, SECONDS)
            if !locked:
                Thread.sleep(500)  // 等待其他线程回填完成
                return
            
            // Step 4: 双重检查（DCL）
            if redisTemplate.hasKey(key(MESSAGE_KEY, sessionId)):
                return  // 其他线程已完成回填
            
            // Step 5: 从MySQL回填最近8轮对话（时间正序）
            messages = chatHistoryRepository.findTop16BySessionIdOrderByCreatedAtAsc(sessionId)
            for msg in messages:
                shortTermMemory.saveMessage(sessionId, msg.getRole(), msg.getContent())
            
            // Step 6: 从MySQL回填PENDING待办事项
            todos = sessionTodoRepository.findBySessionIdAndStatus(sessionId, "PENDING")
            for todo in todos:
                shortTermMemory.saveTodo(sessionId, todo.getTodoContent())
            
            log.info("冷启动恢复完成: sessionId={}, messages={}, todos={}", 
                     sessionId, messages.size(), todos.size())
        
        catch InterruptedException e:
            log.error("冷启动恢复获取锁超时", e)
            throw new MemoryRecoverException(sessionId, "冷启动恢复获取锁超时")
        
        finally:
            if lock.isHeldByCurrentThread():
                lock.unlock()
```

### 18.4 DiscountMatrix折扣矩阵伪代码

```pseudo
@Component
class DiscountMatrix:
    // 折扣率阶梯表（基于订购量）
    Map<Integer, Double> discountRateTable = {
        50: 0.05,    // 50件起 5%折扣
        100: 0.10,   // 100件起 10%折扣
        500: 0.15,   // 500件起 15%折扣
        1000: 0.20   // 1000件起 20%折扣
    }
    
    function calculate(productId: String, expectedPrice: BigDecimal, quantity: int) -> QuoteResult:
        // Step 1: 获取产品价格信息（模拟从产品系统获取）
        product = getProductInfo(productId)
        currentPrice = product.getCurrentPrice()
        minPrice = product.getMinAcceptablePrice()
        
        // Step 2: 计算批量折扣率
        discountRate = getDiscountRate(quantity)
        
        // Step 3: 计算可接受价格
        acceptablePrice = currentPrice * (1 - discountRate)
        acceptablePrice = Math.max(acceptablePrice, minPrice)  // 不低于最低价
        
        // Step 4: 判定结果
        if expectedPrice >= acceptablePrice:
            finalPrice = Math.min(expectedPrice, acceptablePrice)
            return QuoteResult(accepted=true, finalPrice=finalPrice, minPrice=minPrice)
        else:
            return QuoteResult(accepted=false, finalPrice=null, minPrice=acceptablePrice)
    
    // 获取折扣率
    function getDiscountRate(quantity: int) -> double:
        rate = 0.0
        for (threshold, discount) in discountRateTable:
            if quantity >= threshold:
                rate = Math.max(rate, discount)
        return rate
```

### 19.2 MqProducer伪代码

```pseudo
@Component
class MqProducer:
    @Autowired RocketMQTemplate rocketMQTemplate
    
    // 发送压缩消息
    function sendCompress(compressMsg: CompressMessage):
        sendWithRetry(COMPRESS_TOPIC, COMPRESS_TAG, compressMsg)
    
    // 发送持久化消息
    function sendPersist(persistMsg: PersistMessage):
        sendWithRetry(PERSIST_TOPIC, PERSIST_TAG, persistMsg)
    
    // 带重试的消息发送
    @Retry(name = "mqProducer")
    function sendWithRetry(topic: String, tag: String, message: Object):
        destination = topic + ":" + tag
        try:
            rocketMQTemplate.syncSend(destination, message)
        catch Exception e:
            log.error("MQ消息发送失败: topic={}, msg={}", topic, e.getMessage())
            throw e  // 让Resilience4j重试
    
    // 重试3次仍失败的补偿处理
    function sendWithCompensation(topic: String, tag: String, message: Object):
        for i from 1 to 3:
            try:
                sendWithRetry(topic, tag, message)
                return
            catch Exception e:
                if i == 3:
                    // 记录补偿日志，后续人工处理
                    log.compensation("MQ消息发送失败需补偿: topic={}, message={}", topic, message)
```

```pseudo
    function updateSingleUser(userId: String):

            userId, LocalDateTime.now().minusDays(2)

            return  // 没有新事实，跳过

        if newHabits != oldProfile.get().getBusinessHabits():
```

```pseudo
    function recover(@RequestBody @Valid SessionRecoverRequest request) -> Result<SessionRecoverResponse>:
        coldStartRecovery.recoverIfNeeded(request.sessionId, request.userId)
        
        messageCount = shortTermMemory.loadRecentMessages(request.sessionId).size()
        todoCount = shortTermMemory.loadTodos(request.sessionId).size()
        
        return Result.success(new SessionRecoverResponse(
            request.sessionId, true, messageCount, todoCount
        ))
    
    // 结束会话
    @PostMapping("/close")
    function close(@RequestBody SessionCloseRequest request) -> Result<Void>:
        shortTermMemory.deleteSession(request.sessionId)
        return Result.success(null)
```

### 24.3 CrossTradeService核心处理服务伪代码

```pseudo
@Service
class CrossTradeService:
    @Autowired InboundGuardrail inboundGuardrail
    @Autowired MemoryManager memoryManager
    @Autowired IntentIdentifier intentIdentifier
    @Autowired IntentRouter intentRouter
    @Autowired OutboundGuardrail outboundGuardrail
    @Autowired StreamCompleteCallback streamCompleteCallback
    @Autowired MetricsCollector metricsCollector
    
    // 核心处理方法（流式）
    function process(request: ChatRequest) -> Flux<String>:
        // Step 1: 入口安全审查
        checkResult = inboundGuardrail.check(request.message, request.sessionId, request.userId)
        if checkResult == BLOCK:
            return Flux.just("您的消息包含敏感内容，请重新描述")
        
        // Step 2: 加载记忆上下文（缓存击穿时触发冷启动恢复）
        context = memoryManager.buildContext(request.sessionId, request.userId, request.message)
        
        // Step 3: 意图识别与路由
        intentResult = intentIdentifier.identify(request.message)
        context.setIntentResult(intentResult)
        
        // Step 4: 业务处理（流式生成）
        responseFlux = intentRouter.route(intentResult, context)
        
        // Step 5: 出口安全审查 + 流式输出
        StringBuilder fullResponse = new StringBuilder()
        return responseFlux
            .doOnNext(token -> {
                // 累积完整响应
                fullResponse.append(token)
                // 出口审查缓冲校验
                outboundGuardrail.checkAndEmit(token, emitter)
            })
            .doOnComplete(() -> {
                // Step 6: 流式输出完成回调
                streamCompleteCallback.onComplete(
                    request.sessionId, request.userId,
                    request.message, fullResponse.toString(), 0
                )
            })
    
    // 同步处理方法（调试用）
    function processSync(request: ChatRequest) -> String:
        return process(request).collectList()
            .map(tokens -> String.join("", tokens))
            .block()
```
